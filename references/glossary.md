# 용어집

수업에서 처음 나오는 용어를 회차 순서로 모았습니다. 코드 예는 이 저장소의 파일에서 가져왔습니다. 전술의 사용법은 [빠른 참고](lean-cheatsheet.md), 모델의 정확한 의미는 [semantics.md](semantics.md)에 있습니다.

## Lean 기본 문법 (1회차)

| 용어 | 뜻 | 예 |
|---|---|---|
| `def` | 함수나 값을 정의합니다. | `def step (s : State) (e : Event) : State := ...` |
| `inductive` | 가능한 경우를 나열해 새 타입을 만듭니다. 각 경우를 생성자라고 합니다. | `Phase`는 `idle`과 `waiting` 둘뿐입니다. |
| `structure` | 여러 필드를 하나로 묶은 타입입니다. | `State`는 `phase`와 `sent`를 가집니다. |
| 기본값 `:= ...` | 필드를 정하지 않으면 쓰이는 값입니다. | `sent : Nat := 0` |
| `{}` | 모든 필드가 기본값인 값입니다. | `{} : State`는 `idle, 0` |
| `⟨a, b⟩` | 필드를 선언 순서대로 적어 구조체 값을 만드는 표기입니다. | `⟨.idle, 3⟩` |
| `.name` | 타입을 문맥으로 알 수 있을 때 `Type.name`을 줄여 쓴 표기입니다. | `.idle`은 `Phase.idle` |
| `{ s with f := v }` | `s`에서 필드 `f`만 바꾼 새 값입니다. `s`는 바뀌지 않습니다. | `{ s with phase := .idle }` |
| `match` | 위에서부터 차례로 패턴을 비교해 처음 맞는 줄을 씁니다. | `step`의 본문 |
| `_` | 패턴에서 “무엇이든”을 뜻합니다. 앞 줄에서 처리하지 않은 경우를 받습니다. | `\| _, _ => s` |
| `deriving Repr, DecidableEq` | 값을 출력하는 기능(`Repr`)과 `=`로 비교하는 기능(`DecidableEq`)을 자동으로 만듭니다. | 타입 정의 끝의 줄 |
| `Nat` | 0, 1, 2, … 자연수 타입입니다. | `sent : Nat` |
| `A → B` | A를 받아 B를 돌려주는 함수의 타입입니다. | `State → Event → State` |
| `#check` | 식의 타입을 보여 줍니다. | `#check step` |
| `#eval` | 식을 계산해 결과를 보여 줍니다. | `#eval step {} .send` |
| `#guard` | 계산 결과가 참인지 검사합니다. 거짓이면 오류가 납니다. | `#guard run {} normal = completed 1` |
| 타입 오류 | 값의 타입이 요구되는 타입과 맞지 않아 Lean이 실행 전에 알려 주는 오류입니다. 결과값이 기대와 다른 문제와는 다릅니다. | 반환 타입을 `Nat`으로 바꾼 경우 |

## 값의 종류 (2회차)

| 용어 | 뜻 | 예 |
|---|---|---|
| `Option T` | 값이 없거나(`none`) `T` 값 하나가 있는(`some v`) 두 경우뿐인 타입입니다. | `pending : Option Nat` |
| `A × B` | 두 값을 한 쌍으로 묶은 타입입니다. 값은 `(a, b)`로 씁니다. | `State × List Action` |
| `List T` | `T`의 목록입니다. `[]`는 빈 목록, `e :: es`는 맨 앞 `e`와 나머지 `es`입니다. | `List Event` |
| `xs ++ ys` | 두 목록을 이어 붙입니다. | 큐 뒤에 메시지 추가 |
| 재귀 | 함수가 자기 자신을 다시 부르는 정의입니다. | `run` |
| `Bool` | `true`나 `false`입니다. 코드의 계산과 `if` 조건에 씁니다. | `n == k` |
| `Prop` | 참·거짓을 주장하는 명제의 타입입니다. 정리에서 증명하는 대상입니다. | `n = k`, `n ≠ k` |
| `==`와 `=` | `==`는 Bool을 돌려주는 계산용 비교, `=`는 “같다”는 명제입니다. | `if n == k` / `advance s .timeout = s` |

## 증명 (2~4회차)

| 용어 | 뜻 | 예 |
|---|---|---|
| `theorem` | 이름 붙은 정리입니다. 콜론 뒤가 주장이고 `:= by` 뒤가 증명입니다. | `theorem idle_timeout` |
| `example` | 이름 없는 정리나 검사입니다. | 연습 E5의 시작 파일 |
| 가정 `h : P` | “P가 참이다”라는 증거 `h`를 이미 가진 상태입니다. | `(h : n ≠ k)` |
| `∀` | “모든 … 에 대해”입니다. | `∀ s ∈ history {} events, Inv s` |
| `∧` | “그리고”입니다. `h.1`, `h.2`로 두 부분을 꺼냅니다. | `Inv s`는 `Safe s ∧ QueueValid s` |
| `∈` | 목록에 속한다는 뜻입니다. | `s ∈ history {} events` |
| 목표(goal) | 지금 증명해야 하는 명제입니다. Infoview에서 `⊢` 아래에 나옵니다. | |
| Infoview | VS Code에서 현재 가정과 목표를 보여 주는 창입니다. `⊢` 위가 가정입니다. | |
| `rfl` | 양쪽을 계산하면 같다는 증명입니다. | `idle_timeout` |
| `simp [f, h]` | 정의 `f`를 펼치고 사실 `h`를 써서 식을 단순화합니다. | `wrong_ack` |
| `cases x` | `x`가 될 수 있는 모든 경우로 나눕니다. | `cases p`는 `none`과 `some _` |
| `t1 <;> t2` | `t1`이 만든 모든 경우에 `t2`를 적용합니다. | `cases p <;> simp [advance, step]` |
| `intro` | “모든 x”나 “A라면”의 변수와 가정을 꺼냅니다. | `intro s hs` |
| `exact h` | 목표와 같은 타입의 증거 `h`를 제시합니다. | `exact h.1.1` |
| `constructor` | `A ∧ B` 목표를 `A`와 `B` 두 목표로 나눕니다. | E7 |
| `apply lemma` | 정리의 결론을 목표에 맞추고, 정리의 전제를 새 목표로 만듭니다. | `apply ih` |
| `induction` | 목록이나 자연수에 대해 “기본 경우”와 “한 칸 늘어난 경우”로 나누어 증명합니다. 한 칸 늘어난 경우에서는 줄어든 쪽에 대한 가정(귀납 가정, `ih`)을 쓸 수 있습니다. | `run_preserves` |
| `generalizing s` | 귀납 중에 `s`가 바뀔 수 있으니, 특정 `s`가 아닌 모든 `s`에 대한 가정을 얻게 합니다. | `induction es generalizing s` |
| `omega` | 자연수의 선형 부등식을 풀어 주는 자동 도구입니다. 제공된 증명에서 쓰입니다. | `valid_mono` |
| 반례 | 주장이 틀렸음을 보이는 구체적인 입력입니다. | `some 7` 상태에서 `ack 6` |

## 프로토콜 (2~3회차)

| 용어 | 뜻 |
|---|---|
| 패킷 | 번호로 구분되는 전송 단위입니다. 이 모델에서는 내용 없이 번호만 있습니다. |
| ACK | 수신 확인입니다. `ack n`은 `n`번 데이터를 받았다는 뜻입니다. |
| timeout | 정해진 시간 안에 ACK가 오지 않았음을 나타내는 이벤트입니다. 실제 시계를 쓰지 않고 이벤트로 표현합니다. |
| 재전송 | timeout 때 같은 번호의 데이터를 다시 보내는 것입니다. |
| `pending` | 2회차에서 ACK를 기다리는 패킷 번호입니다. 없으면 `none`입니다. |
| `sender.next` | 3회차 이후 송신자의 다음 전송 번호이자 ACK로 확인한 개수입니다. |
| `receiver.next` | 수신자가 다음에 받을 번호이자 받아들인 개수입니다. |
| `waiting` | 송신자가 보낸 데이터의 ACK를 기다리는 중인지 나타냅니다. |
| 큐 (FIFO) | 먼저 들어온 메시지가 먼저 나가는 목록입니다. 이 모델의 큐에는 `data n`과 `ack n`이 함께 들어 있습니다. |
| `deliver` | 큐의 맨 앞 메시지 하나를 받는 쪽에 전달합니다. |
| `drop` | 큐의 맨 앞 메시지를 잃습니다. |
| `duplicate` | 큐의 맨 앞 메시지를 연속 두 개로 만듭니다. |
| 오래된 데이터·ACK | 번호가 이미 처리한 범위에 속하는 메시지입니다. 데이터는 다시 세지 않고 ACK만 다시 보내며, ACK는 진행시키지 않고 버립니다. |
| 환경 | 어떤 이벤트가 일어날지 고르는 쪽입니다. 모델은 손실과 중복을 환경이 고른다고 봅니다. |

## 모델과 증명의 구조 (2~4회차)

| 용어 | 뜻 | 위치 |
|---|---|---|
| 상태(State) | 어느 한 순간의 모든 정보를 담은 값입니다. | `State` |
| 이벤트(Event) | 밖에서 일어난 일입니다. | `Event` |
| 전이 | 상태와 이벤트로 다음 상태를 정하는 것입니다. | `step` |
| 거절 | 전이가 `none`을 돌려주는 것입니다. 이 저장소의 실행기는 거절된 이벤트를 무시하고 상태를 유지합니다. | `advance` |
| `advance` | 이벤트 하나를 적용합니다. 거절이면 현재 상태를 돌려줍니다. | `Protocol.lean` |
| `run` | 이벤트 목록을 차례로 적용해 최종 상태를 돌려줍니다. | `Protocol.lean` |
| trace | 이벤트의 열(목록)입니다. 한 번의 실행을 나타냅니다. | |
| `history` | 초기 상태와 모든 중간 상태의 목록입니다. 이벤트가 n개면 상태가 n+1개입니다. | `Protocol.lean` |
| Action | 전이에서 일어난 일의 기록입니다. 이미 상태에 반영된 뒤이므로 다시 적용하지 않습니다. | `Action` |
| AST | 동작을 뜻하는 자료입니다. 여기서는 `Guard`, `Action`, `Rule`을 가리킵니다. | 4회차 |
| `Guard` | 규칙이 적용되는 조건입니다. `evalGuard`가 참·거짓을 계산합니다. | 4회차 |
| `Rule` | 이벤트, guard, 명령 목록의 세 필드를 가진 규칙입니다. | 4회차 |
| `interpret` | 규칙 목록에서 이벤트가 같고 guard가 참인 첫 규칙 하나를 골라 실행합니다. | 4회차 |
| `directStep` | 규칙표 없이 직접 쓴 전이 함수입니다. `interpreter_matches_direct`가 `step`과 결과가 같음을 보입니다. | 3~4회차 |
| 불변식 | 도달 가능한 모든 상태에서 항상 참이어야 하는 조건입니다. | `Inv` |
| `Safe` | `sender.next ≤ receiver.next ≤ sender.next + 1`입니다. | `Invariants.lean` |
| `QueueValid` | 큐의 data 번호는 발급 범위 안, ACK 번호는 이미 받은 수보다 작다는 조건입니다. | `Invariants.lean` |
| 보존 | `Inv s`가 참이면 한 단계 뒤의 상태도 `Inv`가 참이라는 뜻입니다. | `*_preserves` |
| 국소 보존 | 특정 이벤트가 일부 필드만 유지한다는 좁은 성질입니다. | `timeout_local` |
| safety | “잘못된 일이 일어나지 않는다”는 성질입니다. 유한한 실행 하나로 위반을 보일 수 있습니다. | |
| liveness | “좋은 일이 결국 일어난다”는 성질입니다. 이 저장소는 증명하지 않습니다. | |
| 도달 불가능 | 초기 상태에서 어떤 이벤트 열로도 만들 수 없는 상태입니다. 타입으로 표현할 수 있다는 것과 다릅니다. | `bad_unreachable` |
